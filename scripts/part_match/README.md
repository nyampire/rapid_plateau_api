# 転記元を外形と part のどちらに取るかを測る

PLATEAU の建物と OSM の建物を突き合わせ、タグ転記の転記元を建物外形に取る場合と
`building:part` に取る場合で、何棟が拾えて何棟の値が変わるかを数える。

[Rapid#43](https://github.com/nyampire/Rapid/issues/43) の議論に使った計測を、
別の都市や再取り込みの後にもう一度回せるように残したもの。

## 何が起きているか

PLATEAU では複数の棟から成る 1 つの建物でも、OSM では棟ごとに別々の建物として
描かれていることがある。
現在の照合は転記元を `building` を持ち `building:part` を持たない要素に限り、
外形の代表点を含む OSM 建物 1 つだけを相手にする。
そのため OSM が分かれている建物では、片方だけが候補になり、もう片方は候補にならない。

外形の高さはその建物で一番高い棟の高さなので、候補になった側にも建物全体の高さが入る。
値が違うとき、低く出る例は無く、必ず高く出る。

## 使い方

3 段に分かれる。1 段目と 2 段目は入力を作り、3 段目が数える。

### 1. PLATEAU 側を書き出す

データベースに届く場所で実行する。接続文字列は引数か環境変数 `DATABASE_URL` で渡す。

```bash
python3 export_city.py 39201 --postgres-url "$DATABASE_URL" -o plateau_39201.csv.gz
```

API の入口フィルタと同じ条件を掛けるので、隣接市の配布に含まれる重複は入らない。
出力は 1 行 1 建物で、ジオメトリは WKB の 16 進で持つ。

### 2. OSM 側を切り出す

[Geofabrik](https://download.geofabrik.de/asia/japan.html) の PBF と `osmium-tool` を使う。
日本全体は 2.5GB あるので、建物だけに絞ってから範囲を切る。

```bash
# 建物だけに絞る (1 回だけ。10 分ほどかかる)
osmium tags-filter -o japan-buildings.osm.pbf japan-latest.osm.pbf nwr/building nwr/building:part

# 都市の範囲を切り出す。bbox は書き出した CSV の範囲に少し余裕を足す
osmium extract -b 133.470,33.524,133.579,33.592 -o osm_39201.osm.pbf japan-buildings.osm.pbf

# 解析が読む形式に変換する
osmium export -f geojsonseq --add-unique-id=type_id -o osm_39201.geojsonseq osm_39201.osm.pbf
```

`osmium export` は閉じた way を LineString と (Multi)Polygon の 2 つで出す。
解析は面のほうだけを読む。

### 3. 数える

```bash
python3 analyze.py --plateau plateau_39201.csv.gz --osm osm_39201.geojsonseq
```

## 出力の読み方

前半は現在の実装で何が起きているかを示す。

- `part を持つ外形の下にある OSM 建物` は、外形の中に代表点が落ちる OSM 建物の数
- `OSM が 2 棟以上に分けているもの` が、この計測の主題
- `いま候補にならず height も無い OSM` が取りこぼし
- `いま高すぎる値が入る OSM` は、候補になった側に建物全体の高さが入っているもの

後半の表は、転記元を part に切り替える門の高さを変えたときの増減を示す。
「差」は、OSM 建物と part の形の一致から、OSM 建物と外形の形の一致を引いた値の下限である。
この差を超えたときだけ part を採る。

- `新たに拾える` は、いま候補にならず height も無い OSM が part で拾えるようになる数
- `高すぎた値が直る` は、いま入っている値が対応する棟の高さに変わる数
- `正しかった値が変わる` は、建物全体を 1 つの way で描いている OSM の値が変わってしまう数

## 4 都市の結果 (2026-08-20)

OSM は Geofabrik の日本全体 2026-08-19 時点。

| 都市 | PLATEAU 外形 | part を持つ外形 | OSM 建物 | 取りこぼし | 高すぎる値 |
|---|---|---|---|---|---|
| 高知市 39201 | 78,383 | 16,243 | 40,670 | 2,990 | 793 |
| 岡崎市 23202 | 205,530 | 6,815 | 53,895 | 780 | 162 |
| 豊田市 23211 | 302,054 | 24,824 | 105,849 | 1,307 | 346 |
| 横浜市 14100 | 868,611 | 9,632 | 1,337,904 | 3,404 | 1,117 |

4 都市を合わせた門ごとの増減。

| 差 | 新たに拾える | 高すぎた値が直る | 正しかった値が変わる | うち 2m 以上 |
|---|---|---|---|---|
| 0.00 | 8,559 | 4,000 | 1,028 | 132 |
| 0.05 | 7,218 | 3,465 | 482 | 38 |
| 0.10 | 6,810 | 2,867 | 157 | 11 |
| 0.20 | 6,224 | 1,829 | 0 | 0 |
| 0.30 | 5,587 | 1,159 | 0 | 0 |

差 0.20 なら、いまより悪くなる箇所を出さずに拾える数を増やせる。

## この計測の限界

OSM の multipolygon relation は数えていない。
`osmium export` が部材の欠けた relation を落とすためだが、現在の照合も OSM 側を way に
限っているので、見え方は一致する。

「建物全体を写しているか、棟 1 つだけか」の切り分けに、外形の 80% を覆うかという境目を
置いている (`rules.DEFAULT_WHOLE_THRESHOLD`)。
差 0.20 で悪化が 0 になるのは、この境目の取り方に依存する。

外形とほぼ同じ大きさの part を持つ建物が 4 都市で 10% から 19% ある。
[api#33](https://github.com/nyampire/rapid_plateau_api/issues/33) が指す重複だが、
外形とほぼ同じ形なので差の門を越えられず、この計測の結論は変わらない。

## ファイル

| ファイル | 用途 |
|---|---|
| `rules.py` | 転記元の選び方と閾値。幾何を持たない判定だけ |
| `export_city.py` | 1 都市の外形と part を CSV に書き出す |
| `analyze.py` | OSM と突き合わせて表を出す |

テストは `tests/test_part_match_rules.py` と `tests/test_part_match_analyze.py` にある。
