# 高さが怪しい PLATEAU の建物をエディタで知らせる

## 目的

PLATEAU の建物の高さには誤りが含まれます。
`docs/height-outlier-survey.md` の調査では、5 つの検査で約 29 万件が見つかりました。

エディタの利用者が、誤った高さをそのまま OSM に入れるのを防ぎたいと考えています。
そのために、高さが怪しい建物を、利用者が追加するかを決める時点で知らせます。

## 知らせる時点

PLATEAU の高さが OSM に入る道は 2 つあります。

1. 新しい建物の追加です。
   PLATEAU の建物を選ぶと、サイドバーにタグの一覧と「この地物を追加」「無視」が出ます。
   A キーは「この地物を追加」と同じ処理です。
2. 既存の OSM 建物へのタグの転記です。
   OSM の建物を選ぶと PLATEAU のタグを移す欄が出て、「適用」で高さが書き込まれます。

警告は、建物を選んだ時点でサイドバーに出します。
A キーを押した時点では止めません。

A キーの時点で止めない理由は 3 つあります。

- 利用者が追加するかを決めるのは、選んでサイドバーを見たときです。
- 追加のたびに確認の画面を出すと、続けて追加する作業が毎回止まります。
- 追加の方法は A キーのほかに、ボタン、「この地物のみ追加」、追加してからの移動や回転があります。
  選んだ時点で出せば、どの方法でも警告を見てから操作することになります。

タグの転記の欄にも、同じ警告を出します。
転記の道を通ると、警告なしで同じ高さが入ってしまうためです。

## 警告に使う検査

調査の 5 つの検査のうち、次の条件に当てはまるものだけを警告にします。

| 検査 | 警告にする条件 | 件数（2026-09-28） |
|---|---|---:|
| `degenerate-area` | すべて | 7 |
| `part-over-outline` | すべて | 37 |
| `needle` | 部分立体を除く | 22,893 |
| `absolute` | 下側（高さ 1.0 m 未満）だけ | 3,404 |
| `floor-height` | `building` が `house`、`apartments`、`residential` のものだけ | 127,916 |

重なりを除かずに足すと、約 16 万件です。

外したものと、その理由です。

- `needle` の部分立体（6,694 件）は、屋上の塔屋や階段室が多く、正常な構造物なので外します。部分立体の高さは地面から測るため、高層の建物の屋上にある小さな部分が条件に当てはまります。
- `absolute` の上側（200 m 超、56 件）は、実在する超高層建築と見分けられないので外します。
- `floor-height` の住宅以外（134,093 件）は外します。
  工場（`industrial`）、倉庫（`warehouse`）、公共施設（`public`）は 1 階が高いことが多く、正常な建物に警告が出てしまうためです。
  警告が多すぎると、利用者が警告を読まなくなるおそれがあります。

## 全体の流れ

```
API（rapid_plateau_api）
  建物を返すときに判定を行い、該当した建物に目印のタグを添える
      ↓
エディタ（Rapid）
  受け取った時点で目印のタグを取り除き、建物のデータに警告として持たせる
      ↓
  ├ 地図: 警告のある PLATEAU の建物を点の模様で塗る
  ├ サイドバー: 選んだ建物の警告を、タグ一覧の上に出す
  └ タグ転記: 警告のある候補の印を赤い縁と「!」にし、転記の欄にも警告を出す
```

## API での判定

### 判定を行う場所

API が建物を返すときに、その範囲の建物だけを判定します。
調査の結果をデータベースに保存する方法は採りません。
取り込みのたびに作り直す必要があり、調査スクリプトが読むだけという前提も崩れるためです。

5 つの判定のうち 3 つは、API が今すでに取り出している値だけで判定できます。

| 判定 | 使う値 | 問い合わせへの追加 |
|---|---|---|
| `absolute` の下側 | 高さ | なし |
| `floor-height` | 高さ、階数、`building` | なし |
| `part-over-outline` | 部分立体と外形の高さ | なし（外形は同じ応答に含まれます） |
| `degenerate-area` | 平面での面積 | 面積の列を足します |
| `needle` | 高さ、平方メートルでの底面積 | 同上 |

`needle` の底面積は、平面での面積が正のときだけ球面上で計算します。
面積が 0 以下の輪郭は、球面上の計算をエラーで止めるためです。
この扱いは調査スクリプトと同じです。

### 閾値の共有

判定の条件の値は、`plateau_height_outliers.py` の `DEFAULT_` で始まる定数を読み込んで使います。
調査と警告で閾値がずれないようにするためです。

判定の処理そのものは、調査スクリプトが SQL で、API が Python で持ちます。
同じ建物に対して両者が同じ結果を返すことを、統合試験で確かめます。

### 目印のタグ

該当した建物の way に、`plateau:height_warning` というタグを添えます。
値は該当した検査の名前を `;` でつないだものです（例: `needle;floor-height`）。
外形の way の値は、建物の relation にも複製します。
既存のタグと同じ扱いです。

警告の文に実際の値を入れるため、判定に使った値もエディタで読めるようにします。
高さと階数はすでにタグで届きます。
`part-over-outline` の外形の高さは、同じ応答の外形の way から読めます。
`needle` の底面積だけは届いていないので、`plateau:footprint_m2` として添えます。

### 応答時間

面積の計算が 1 棟ごとに増えます。
球面上の面積は、平面での面積が正で、かつ高さが needle の下限（15 m）を超える建物だけで計算します。
needle はその条件の建物しか見ないため、この絞り込みで結果は変わりません。
本番データベースで、建物の密集した 0.02 度四方の範囲 2 か所（大阪中心部、新宿中心部）を使い、5 回の中央値で応答時間を測りました。
行数は変更の前後で一致し、応答時間は大阪で +1.7%、新宿で +1.4% でした。

## エディタでの表示

### 目印のタグの取り除き

`PlateauService` が API の応答を読むときに、`plateau:height_warning` と `plateau:footprint_m2` を取り除きます。
`representative_point` を取り除いているのと同じ場所です。
取り除いた値は、建物のデータの内部の属性として持ちます。

これで、建物を追加しても目印のタグは OSM に送られません。

### 地図

警告のある PLATEAU の建物は、塗りを点の模様（`dots`）にします。
色はデータセットの色（マゼンタ）のままです。

OSM レイヤーを消しているときは、今と同じく斜線の模様（`construction`）にします。
2 つが重なる場合は、斜線を優先します。
追加できない状態を示すほうが、先に伝える必要があるためです。

### サイドバー

PLATEAU の建物を選んだときに、タグ一覧の上に警告の欄を出します。
検査ごとに、実際の値を入れた一文で理由を示します。

| 検査 | 文の例 |
|---|---|
| `degenerate-area` | 輪郭が壊れていて、面積が 0 以下です |
| `part-over-outline` | 建物の一部（149.2 m）が、建物全体（9.1 m）より 140.1 m 高くなっています |
| `needle` | 高さ 18.4 m に対して、底面積が 0.0036 m² しかありません |
| `absolute` | 高さが 0.5 m で、建物としては低すぎます |
| `floor-height` | 1 階あたりの高さが 12.3 m で、住宅としては高すぎます |

文の最後に、高さを確かめるよう促す一文を添えます。

部分立体を持つ建物は、1 つを選んで追加すると建物全体が追加されます。
そのため、一緒に追加される部分立体の警告もまとめて出します。
「この地物のみ追加」を選んだ場合に追加されるのは選んだ way だけですが、警告は選んだ時点で出すので、全体の警告を出したままにします。

追加の操作は止めません。

### タグの転記

転記の候補の印は、今はマゼンタの丸です。
転記元の PLATEAU の建物に警告があるときは、マゼンタの丸に赤い縁を付け、中に「!」を描きます。
既存の「!?」は「OSM の値と食い違う」「面積が合わない」の意味で使っているので、別の印にします。

転記の欄にも、サイドバーと同じ警告の文を出します。
「適用」の操作は止めません。

### 文言の翻訳

警告の文は、エディタの翻訳の仕組みに英語と日本語で登録します。

## 試験と確認

API

- 判定の関数の単体試験を、検査ごとに書きます。
  境界の値（高さ 1.0 m ちょうど、1 階あたり 10.2 m ちょうどなど）を含めます。
- 面積の列の統合試験を書きます。
  面積が負の輪郭で API が止まらないことを含めます。
- 同じ建物の集まりに対して、調査スクリプトと API の判定が一致することを確かめます。
- 住宅以外の `floor-height` と、`absolute` の上側に警告が付かないことを確かめます。

エディタ

- `PlateauService` が目印のタグを取り除き、内部の属性として持つこと。
- 追加した建物のタグに、目印のタグが含まれないこと。
- サイドバーに警告の欄が出ること、部分立体の警告もまとめて出ること。
- 塗りの模様が変わること、斜線の模様が優先されること。
- 転記の印と転記の欄の警告が変わること。

本番に出す前に、建物の多い範囲で API の応答時間を測ります。

## 出し方

API とエディタは別のリポジトリなので、Pull Request を 2 つに分けます。

本番には、エディタを先に出し、API をその後に出します。
今のエディタは、API から届いたタグをすべて建物に写します。
API だけを先に出すと、古いエディタで追加した建物に目印のタグが付いたまま OSM に送られます。
反対に、エディタだけを先に出しても、目印のタグが届かないので警告が出ないだけで、害はありません。

## 決めていないこと

- 警告を読まずに追加された建物を、保存の前の「問題」の一覧でもう一度知らせるか。
  今回は入れず、使ってみてから決めます。
- 警告の対象を、利用者が設定で切り替えられるようにするか。
  今回は入れません。
