# 取り込み中の入力の保護と、退避の掃除

- 日付: 2026-08-20
- 関連: [#57](https://github.com/nyampire/rapid_plateau_api/issues/57)（取り込みの走行中に同じ都市を送り直すと、入力が入れ替わる）、[#58](https://github.com/nyampire/rapid_plateau_api/issues/58)（失敗した都市の作業ディレクトリが手元に溜まる）
- 前提: [2026-08-13 の設計](2026-08-13-local-conversion-reimport-design.md)（手元で変換してサーバへ送る取り込み）

## 背景

148 都市の取り込みは、手元で変換して送る第 1 段と、サーバで取り込む第 2 段に分かれる。
2 つの段は順に走らせる約束だが、失敗した都市をやり直したくなるのは第 2 段の走行中である。
その誘惑に対して、いまは仕組みが何も無い。

#57 と #58 はどちらも、148 都市を流している最中に表面化する。
流し始めてからでは直しにくいので、開始前に入れる。

## #57 取り込み中の送り直しで入力が入れ替わる

### いま何が起きるか

送る側は `rsync -az --delete` で都市のディレクトリを同期する。
取り込む側は開始時に `.osm` の枚数と `manifest.txt` を突き合わせるが、その後は見ない。

そのため、取り込みの最中に `--delete` がファイルを消しても、枚数の門は通ったあとになる。
取り込みが成功すると入力のディレクトリを丸ごと消すので、送り直した `.osm` は一度も取り込まれないまま消える。
手元の `shipped.txt` にもサーバの `done.txt` にも成功として残る。

**その都市だけが古いデータのまま残り、どちらの記録からも気づけない。**

いまの枚数の門は、開始時点の一瞬しか保証していない。

### 直し方

転送先と取り込み先を別のディレクトリに分け、取り込み側が rename で自分のものにしてから読む。

```
<転送先の根>/
  .incoming/<都市>/     送る側が rsync する先
  <都市>/               取り込み側が rename で確定した入力
```

rename は同じファイルシステム内で不可分に起きる。
確定したあとの `<都市>/` を送る側が触ることは無いので、走行中に送り直しても取り込み中の入力は変わらない。

**設定値は変えない。** `SHIP_PATH` と `PLATEAU_IMPORT_DIR` はこれまでどおり同じ絶対パスを指す。
`.incoming` を挟むのは 2 本のスクリプトの内部の約束にとどめる。

### 送る側 (`ship_city.sh`) の変更

転送先を `<転送先の根>/.incoming/<都市>/` に変える。

`--delete` は残す。このディレクトリを読むのは送る側だけになるので、消えて困るものが無い。

`.incoming` を挟むと、作る必要のある段が `.incoming` と `<都市>` の 2 つになる。
rsync は宛先の最後の 1 段しか作らないので、rsync の前に ssh で `mkdir -p` する。
転送先の根が存在しないことがあるため、これは既存の手順でも踏んでいる段である。

転送後の枚数の確認先も `.incoming/<都市>` に変える。

### 取り込み側 (`reimport_one.sh`) の変更

ディスクの門を通したあと、既存の入力の検査より前に、確定の段を置く。

| `.incoming/<都市>` | `<都市>` | 動作 |
|---|---|---|
| ある | 無い | rename して確定する |
| ある | ある | 古い `<都市>` を `<都市>.stale` へ退避してから rename する |
| 無い | ある | そのまま使う（落ちたあとのやり直し） |
| 無い | 無い | 従来どおり exit 13 |

「無い / ある」の行が要るのは、確定したあとに落ちると `<都市>` だけが残るためである。
ここで止めると、その都市は手で片付けるまで何度再実行しても失敗し続ける。
夜間に落ちるとそこで 148 都市が止まる。

確定のあとは既存の `manifest.txt` と枚数の門をそのまま通す。
**確定後の入力は送る側が触らないので、この門は初めて意味を持つ。**

### サーバ側の退避は 1 件だけ持つ

`<都市>.stale` は日時を付けず、毎回置き換える。

サーバの空き容量の門は 5GB が既定で、1 都市の入力は最大 4.4GB ある。
退避を積むとこの門に当たる。

残骸が出る条件は「取り込みが落ちたあとに送り直した」ときだけで頻度が低く、
中身は手元から送り直せば再現できるので、履歴を持つ利点が薄い。

**手元とサーバで `.stale` の約束が違う点に注意する。**
手元の `ship_city.sh` は `<都市>.stale.<日時>` を作り、#58 の上限で古いものから消す。
サーバの `reimport_one.sh` は日時を付けない `<都市>.stale` を毎回置き換える。
名前が似ているが別の機械の別の仕組みで、上限の設定を共有しない。

## #58 退避が手元に溜まる

### いま何が起きるか

`ship_city.sh` は 2 種類の退避を作る。

- 失敗したときの `<都市>.failed.<日時>`
- 再実行のときに前回の残骸を退かす `<都市>.stale.<日時>`

どちらも作られるだけで、消す処理が無い。
1 都市で最大 4.4GB 使うので、失敗が重なると手元のディスクを埋める。

黙って壊れるわけではなく、空き容量の門に当たって第 1 段が止まる。
ただし 148 都市を流している最中に止まると、原因が退避の堆積だと気づきにくい。

### 直し方

保持する件数に上限を設け、古いものから消す。あわせて残量を起動時に見せる。

**設定**: `ship.env` に `KEEP_RETAINED_DIRS` を足す。既定は 3、`0` で無効。
`0` を無効とするのは `EARLY_ABORT_FAILS` と同じ約束に揃えるためである。

**数える単位**: `WORK_ROOT` 全体で、2 種類をまとめて数える。
都市ごとに数えると、失敗が多くの都市に散ったときに全体の占有量に上限がかからない。

**掃除する時点**: `ship_city.sh` が退避を作った直後。失敗の経路と、前回を退かす経路の両方に置く。

**並べ替え**: 名前の末尾の日時で行う。日時は `%Y%m%d-%H%M%S` なので、辞書順が時刻順に一致する。

mtime 順にしない。
`mv` はディレクトリの mtime を退避した時刻に更新せず、中身を最後に変えた時刻のまま残すので、実際の退避の順と食い違う。

**残量の表示**: `ship_all.sh` が起動時に、残っている退避の件数と合計サイズを 1 行出す。
上限で自動的に減り、それでも残っている量が目に入る。

## 実装で先に潰す罠

このリポジトリで繰り返し踏んだ型が 3 つある。どれも「壊れているときに限って門が消える」形で出る。

**数値として比べる前に数字か確かめる。**
`KEEP_RETAINED_DIRS` は設定ファイルから来るので、書き損じると
`[ "$n" -gt "$KEEP_RETAINED_DIRS" ]` が integer expression expected でエラー終了し、
`if` がそれを偽として扱う。掃除が黙って飛ぶ。
既存の `need_int` を通し、数字でなければ止める。

**パイプの左側はサブシェルになる。**
退避を数えて変数に残す処理を `... | while read` で書くと、数えた結果が親に伝わらない。
`while read` はプロセス置換かリダイレクトから読む。

**グロブが展開されないときは文字列がそのまま入る。**
退避が 1 件も無いと `"$WORK_ROOT"/*.failed.*` がリテラルのまま `for` に渡る。
`shopt -s nullglob` を使う。既存の `.osm` の検査と同じ形である。

## テスト

既存の `tests/test_ship_city.py` と `tests/test_reimport_one.py` は、PATH に置いた偽コマンドで
`rsync` と `ssh` と `java` を差し替えている。通信も変換もしない。同じ形を使う。

落ちる側と通る側の両方を書く。件数は 2 種類使い、1 つの値に合わせた実装が通らないようにする。

### #57

| 確かめること | 期待 |
|---|---|
| 送る側の宛先 | `.incoming/<都市>/` を指す。rsync の前に `mkdir -p` が走る |
| `.incoming` だけある | rename して取り込む。`.incoming/<都市>` は消える |
| 両方ある | 古い `<都市>` が `<都市>.stale` へ移り、新しい入力で取り込む |
| `<都市>` だけある | rename せずそのまま取り込む |
| どちらも無い | exit 13 |
| 確定後に `.incoming` へ送り直す | 取り込み中の `<都市>` の中身が変わらない |
| `<都市>.stale` が既にある | 日時を増やさず置き換わる。2 件目を作らない |

### #58

| 確かめること | 期待 |
|---|---|
| 上限 3、退避 5 件 | 古い 2 件が消え、新しい 3 件が残る |
| 上限 1、退避 3 件 | 古い 2 件が消え、新しい 1 件が残る |
| 上限 0 | 1 件も消さない |
| 上限が数字でない | 掃除を飛ばさず、止める |
| 退避が 1 件も無い | エラーを出さずに終わる |
| 並べ替え | mtime を作為的にずらしても、名前の日時の順で消える |
| 起動時の表示 | 件数と合計サイズが出る。0 件でも落ちない |

## この変更で直らないもの

第 1 段と第 2 段を並行させてよいことにはならない。
`.incoming` が守るのは「取り込み中の 1 都市の入力」だけで、一覧の置き換えや `done.txt` の競合は対象外である。

取り込みそのものの正しさにも触れない。
枚数の門が意味を持つようになるだけで、中身の検査を増やすわけではない。
取り込んだ行数の突き合わせは #48 が別に扱う。
